## Final Agent Report — Verbatim

**v10.07.01 is done: long unbroken values no longer stack into a tall letter-by-letter column in narrow Sorter cells, and ordinary wrapping and the desktop layout are untouched.** The repair is one CSS rule; the markup, the shared skeleton and the editor are unchanged. I did not commit, push or deploy.

**Baseline.** Project root confirmed. `Agent/retest.html` was v10.07.00, `Agent/retest.txt` byte-identical, `script_changeout.gs` v16.52.1. Git was not clean: the working tree still holds the uncommitted v10.06.00 and v10.07.00 work (the two Stage records are untracked), exactly as at the end of the last task. The page was byte-identical to the v10.07.00 archive, so I went ahead.

1. **Exact overflow cause.** Stage 2 put `overflow-wrap: anywhere` on every cell. That value lets a cell's text shrink to one character wide, and it breaks a word at any letter whenever the line is too narrow, with no minimum. In a cell only 10 to 60 px wide (a heavily divided layout, extreme ratios, or End Cap at phone width) a 40-letter value, or even "HEAT PUMP", took one letter per line. In my fixture the worst cell took 56 lines, so a row reached 1,340 px.
2. **Exact repair.** Two CSS lines replace the old rule:
   - `.srt-cell { container: srt-cell / inline-size; }`
   - `@container srt-cell (min-width: 8em) { .srt-cell > * { overflow-wrap: anywhere; } }`

   A cell breaks words only when it is at least 8em wide, measured against its own text size. Narrower cells keep the word whole and clip it at the cell edge, as before Stage 2. In a browser without container queries the rule is ignored, which means the old clipping, so there is no risk there. The comments and the version stamps changed too (+23/−19 page lines in total).
3. **Why this beats unrestricted `anywhere`.** It keeps the readable part of the Stage 2 improvement (wide cells still wrap long words, a 40-letter value takes at most 5 lines) and drops the part that created the ribbons. It scales with text size, so a 16 px price cell is never broken (the total price is no longer split across two lines at 360 px). Restoring the old clipping wholesale would have lost the wrapping in the default layout.
4. **Desktop.** The default and 22-mapping layouts (End Cap on and off, ordinary long text and the 40-letter value) are identical to v10.07.00 and to Stage 1, in every row, stack, container and cell. The six-system characterization at desktop width is identical too, markup included. In the heavily divided layouts at desktop width, a few narrow cells go back to clipping their long words and the row heights equal the Stage 1 heights. One of them, the extreme-ratio layout, falls from 378 to 149 px.
5. **390 px.** The default layout is identical to Stage 1. The brand text still wraps in its 117 px cell. The 22-mapping stress layout with End Cap returns to the Stage 1 geometry.
6. **360 px.** The default layout has the Stage 1 row heights. The long brand word still wraps in its 103 px cell in 5 lines. The only cell that changes is the narrow total-price cell (52 px at 16 px text), whose number goes back to one line instead of being split.
