## Final Agent Report — Verbatim

**v10.08.01 — Stage 3B done (composite static text). Nothing committed, pushed or deployed.**

1. **Token data model.** `compositeFields` stays one ordered array. A field token is `{ field, showLabel }` (unchanged); a static text token is `{ type: 'text', text }`. Old layouts need no migration; schemaVersion 3 and the storage key `changeout_cart_mapping_v3` are unchanged.
2. **Storage / sanitizing.** One sanitizer (`sanitizeSorterText`) is used by the loader and the editor: control characters and line breaks become spaces, whitespace runs collapse, edges trim, maximum 40 characters; an empty text is dropped on load. Invalid entries (null, junk objects) are dropped on load. Rendering escapes the text (`& < > " '`), so it is never HTML.
3. **Editor.** A `+ Add Text` button beside Add Field; a text token shows as a row with a text input (40-character limit, saved on change) and the same up / down / remove controls as a field row. Show Label applies to field rows only. Nothing else in the configurator changed.
4. **Rendering.** Field-only composites go through the unchanged v10.08.00 path. Composites with static text render field tokens exactly as before plus `<span class="srt-static">` spans (no `data-field`).
5. **Separator.** The chosen Separator is used only between two field tokens that touch. Next to a static token the gap is a small plain space.
6. **Blank / punctuation.** A punctuation-only static token (no letter or digit) follows its field neighbours: between two fields it is a joiner (shown only when something is shown before it, it does not follow another joiner, and a non-blank field follows); touching only a field after it (e.g. "(") or before it (e.g. ")", ":") it shows only with that field; with no field neighbour it always shows. Words ("System:", "with") always show. If the composite has fields and all are blank, the cell is N/A. Limit (documented, no grammar): a joiner-like mark after a dropped decoration can still lead the text, e.g. "& RHEEM" when the field before "&" is blank.
7. **Field identity.** Every field token still has its canonical `data-field`; repeated fields work (a field twice in one composite, in several composites and standalone).
8. **Colour.** Unchanged: the established helpers colour systemType, seriesTier, mechanicalStage and applicationStyle inside the value span; static text is plain light grey.
9. **Saved layouts.** The baseline and new page render the field-only fixture identically (text, tokens, separators, colours, row heights, every viewport and End Cap state). A saved layout with static tokens reloads in the same order and text; hostile stored data (null, junk, whitespace-only, a number, an 80-character text, a token with both `type: text` and a field) loads safely.
10. **Editor / runtime parity.** The preview uses the same renderer; its tokens, static texts and separators match the rows (the only difference is a standalone single-field cell, which the preview still labels with its name, as before).
11. **Mobile.** 390 px and 360 px: page overflow 0, no row overflow. The deliberately heavy five-stack fixture grows rows at phone width (about 180 to 395 px, as a narrow cell wraps); nothing is clipped sideways and the layout is not pathological. Desktop rows stay 120 px.
