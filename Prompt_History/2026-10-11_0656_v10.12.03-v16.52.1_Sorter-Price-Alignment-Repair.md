ROOT CAUSE AND EXACT CORRECTION
- Cause (as audited): in renderSorterRow the totalPrice / otdPrice buttons were `w-full h-full flex items-center` with `style="justify-content: inherit"`. The cell is a flex COLUMN, so its justify-content is the vertical alignment; the button is a flex ROW, so the inherited value positioned the price horizontally (Top = left, Middle = centre, Bottom = right) and Horizontal alignment had no effect.
- Fix (Agent/retest.html, renderSorterRow, two buttons only): the button now has `w-full flex flex-col ${priceAlign}` and `style="flex: 1 1 auto"`, where `priceAlign = window.sorterCellAlign(split)` (the cell's own classes: items-* + text-* for horizontal, justify-* for vertical), computed once at the top of cellContent. The button still fills the whole cell (the whole cell is the click target) but is itself aligned with the same rule as every other cell, so nothing is inherited across axes. Colour, weight, size inheritance, hover colour, transition, cursor and onclick="openReceiptModal(index)" are unchanged. No other mapping, no sorterCellAlign / sorterBodyHtml / CSS change, no storage change. The preview needed no change (its placeholder already uses the cell's classes).
