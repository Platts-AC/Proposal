PLATTS PROPOSAL — v10.12.06 PROPOSAL TERMINAL SECURITY REPAIR: FINAL REPORT

Status: implemented and focused-verified. Nothing committed, pushed or deployed. Branch project-main, HEAD 3eb339c.

1. ROOT CAUSES AND AFFECTED FUNCTIONS (confirmed against current source)
- window.updateProposalTerminal (Agent/retest.html): each block's text was inserted as ${b.plain ? escapeProposalBlockHtml(b.text) : b.text}, so every System block (customer fields, Intro / Option overrides, injected note lines) was parsed as HTML; only Custom blocks (plain: true) were escaped. Block texts contain no intentional markup (all block builders produce plain text; only Sorter rows build HTML, in a different renderer).
- The same template put b.target into inline JavaScript handlers (onclick setInsertTarget / openFocusEditor / revertBlockOverride with the id in quotes; ondragstart / ondrop dragBlockStart / dragBlockDrop). Fixed block names are constants; the only untrusted identifier is lineInjections[].id (app-generated INJ_<timestamp>, but loaded and draft state is not validated: normalizeLoadedProposalAppState and the draft loader pass ids through).

2. EXACT CHANGES
- escapeProposalBlockHtml (was & < > only) now delegates to the existing full escaper window.escapePage2HeaderHtml (& < > " '), with the old escaping as fallback; the terminal calls it for EVERY block (the plain flag is no longer needed; Custom blocks are escaped exactly once, not twice). b.text itself, pureCopyText, state, storage and payloads are never encoded; only the HTML built from the text is.
- Controls: the inline onclick / ondragstart / ondragover / ondrop attributes are gone. Buttons carry data-pb-act (insert | edit | revert | delete) plus data-pb-target (attribute-escaped with the same helper; Delete uses data-pb-index as a number), and each block card carries data-pb-block. New bindTerminalControls(terminal) installs ONE set of delegated click / dragstart / dragover / drop listeners per terminal element (guarded by a flag); they read the identifier back from the data attribute and call the unchanged window.setInsertTarget / openFocusEditor / revertBlockOverride / deleteInjection / dragBlockStart / dragBlockOver / dragBlockDrop. Re-rendering replaces the cards, not the listeners.
- Injection target: inj.id ? String(inj.id) : INJ_<i> (same value for every id the app produces; a non-string id can no longer throw).

3. IDENTIFIER COMPATIBILITY
- Ids are treated as opaque strings and are NOT rewritten, renumbered or dropped: output encoding (data attributes) already makes any id inert, so existing saved ids stay compatible, order and references (blockOrder, activeEditTarget, saved edits) are untouched, and a rewrite cannot create collisions. Verified: draft and loaded states with unusual ids (INJ_1700000000000, a quote-and-parenthesis JavaScript breakout string, an id containing quotes, ampersand and tags) restore byte-identical. Pre-existing and unchanged: ids made in the same millisecond can repeat (only possible from scripted input, not from a person).

4. SECURITY TESTS (scratch Edge profile, mocked backend, data: URI payloads only)
- Baseline v10.12.05 with the same data: payloads executed for name, address, email, Intro / Option 1 overrides and a note line (18 executions), and a crafted id executed (ID2).
- v10.12.06: zero executions; no img / b / script / svg elements inside block text; the literal tag text is visible; 4 crafted ids (breakout from a JS string, from an attribute, a closing tag with svg onload) rendered as 4 cards, exact id round trip, zero inline handlers left in the terminal, and Insert Below / Edit Block / Delete clicks plus a drag on each executed nothing (Edit opened the editor on the exact id).
- Ordinary text displays literally: O'Brien, Smith & Sons, A<B and C>D, quoted strings, emoji and accents, multi-line override text.
